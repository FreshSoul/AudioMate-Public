## 1. AudioMate 是什么

AudioMate 是一个**面向游戏音频的 Wwise AI 助手桌面应用**。简单说：

- 你用**中文（或英文）**，它就能帮你查询、分析、操作 Wwise 工程。
- 它能分析音频的**响度、真峰值、频谱**，检测**削波、静音、直流偏移**等缺陷，校验**命名规范和工程结构**。
- 它还能接入**个人知识库、技能（Skill）、插件（Plugin）、MCP 外部系统**，读网页和飞书文档，甚至控制 REAPER。

**核心理念**：你不需要记任何命令或按钮。你只要在聊天框里描述你想做什么，AudioMate 背后的 AI 会自己判断该用哪个工具、怎么操作 Wwise。

## 2. 开始之前：两件必做的准备

启动 `AudioMate.exe` 后，**有两件事必须先做好**，否则它无法正常工作。

### 准备 A：让 AudioMate 能连上 Wwise

AudioMate 通过 **WAAPI**（Wwise Authoring API）和 Wwise 通信，默认端口是 **8080**。

1. **先打开你的 Wwise 工程**（必须先运行 Wwise，AudioMate 不会替你启动它）。
2. 在 Wwise 里**启用 WAAPI**，并允许本机连接（Wwise 菜单 `Project > User Preferences`，勾选启用 WAAPI，默认端口 8080）。
3. AudioMate **启动时不会自动连接**，顶部会显示 `○ Wwise Disconnected`。

> ⚠️ 如果稍后连接失败，通常是：Wwise 没开、WAAPI 没启用，或 8080 端口被防火墙 / 杀毒软件 / 代理工具拦了。

### 准备 B：填入模型密钥（Base URL + API Key）

AudioMate 的“大脑”是一个兼容 OpenAI 接口的大模型，你需要提供访问凭证：

1. 点左侧边栏的 **`⚙ Settings`**（或折叠状态下浮动面板里的 ⚙ 图标）。
2. 设置页默认停在 **`常规`** 这一栏，里面有一张 **`模型服务配置`** 卡片（README 里称为“令牌密钥”，指的就是这张卡片，**并没有一个单独叫“令牌密钥”的标签页**）。
3. 填入：
   - **`Base URL`**：模型服务地址（留空会用默认的远程地址）。
   - **`API Key`**：访问密钥（输入框是密码遮罩，占位符是 `sk-...`）。
4. 点击 **`保存密钥`** 按钮。成功后会弹出提示：`API Key 和 Base URL 已保存并同步`。

> 🔒 密钥安全保存在系统密钥环（keyring）或本地文件 `~/.audiomate_secrets.json`。**不要把密钥发给别人、截图或写进公开文档/技能里。**

## 3. 认识主界面

主窗口分为三块：**左侧 Workspace 侧边栏**、**中间聊天区**、以及顶部状态栏和底部输入区。

### 左侧 Workspace 侧边栏（从上到下）

| 按钮 | 作用 |
|------|------|
| `☰` | 折叠 / 展开侧边栏（折叠后变成一条浮动图标条） |
| `＋ New Chat` | 开始一个新对话 |
| `⏰ 定时任务` | 打开定时任务页（让 AudioMate 定时自动干活） |
| 历史列表 | 点击任意一行，重新打开过去的对话 |
| `📚 Knowledge` | 管理个人知识库 |
| `⚙ Settings` | 配置密钥、Skill、Plugin、MCP、宠物等 |

> 注意：**`Market`（市集）不在左侧边栏**，它通过聊天页的拼图按钮 `🧩` 打开（折叠状态下浮动面板里也有 🧩）。

### 顶部状态栏

- **左侧**：Wwise 连接状态（`○ Wwise Disconnected` / `● Wwise Connected`）+ **`Connect`** 按钮。
- **右侧**：反馈按钮（📷 二维码图标，还能打开本地日志目录）、**`Mode`** 模式下拉（Ask / Agent）、**`Theme`** 主题下拉（Light / Dark）。

**连接 Wwise**：确保 Wwise 已开且 WAAPI 已启用后，点顶部的 `Connect`。连接过程在后台进行，状态会显示 `⏳ 正在连接 Wwise...`，成功后变为 `● Wwise Connected`，按钮变成 `Disconnect`；失败则显示 `○ 请打开Wwise或开启WAAPI`。

### 底部输入区（聊天框）

- **文本框**：输入你的需求，占位符是 `Ask AudioMate...`，**按回车发送**。可以拖入 / 粘贴图片、文件路径、本地文件。
- **底部一排控件**（从左到右）：
  - **模型下拉**：切换本轮使用的模型。
  - **`📚 知识库`**：选择要参考的知识库（不选则自动跨全部知识库匹配）。
  - **Skill 选择器**：默认 `Auto Skill`（自动匹配），也可固定选某个已启用技能。
  - **`🎙` 语音按钮**：调用 Windows 语音输入（仅 Windows，用 Win+H）。
  - **`✈` 发送按钮**：发送消息；任务运行时会变成 `■`，点击可中止。

## 4. 第一次对话：怎么跟 AudioMate 说话

你**用自然语言**驱动一切。在聊天框输入一句话、按回车，AudioMate 就会理解你的意图并回答或动手。

### 它在背后怎么工作（了解即可，无需操心）

AudioMate 没有预设的“按钮动作”。它会**自己写一小段 Python 代码**（在 ` ```python_waapi ` 代码块里），然后在一个**受保护的沙箱**里针对实时的 Wwise 连接运行这段代码，再把结果用大白话总结给你。复杂任务会拆成多步，你会看到一个带编号的进度卡片 `AudioMate 执行中...`。

> 你**完全不用写代码**，只管提需求。

### 关键概念：“选中对象（selection）”

很多操作针对“**当前选中的对象**”——指的是你**在 Wwise 的 Project Explorer 里高亮选中的对象**，不是在 AudioMate 里选。

**正确流程**：先切到 Wwise → 点选（或 Ctrl/Shift 多选）你要操作的对象 → 回到 AudioMate → 说“选中对象 / the selected object”。AudioMate 每一轮都会实时读取你在 Wwise 里的选择。

> 如果 Wwise 里什么都没选，针对选中对象的请求会返回空，AudioMate 会如实说“没有可操作的对象”，而不会瞎猜。

### 怎么把话说清楚

按 **「意图 + 对象 + 数值」** 来说，结果最准：

- ✅ 好：「把**选中对象**的 Volume 设为 **-6 dB**」
- ✅ 好：「列出**当前工程**里所有的 Event」
- ⚠️ 含糊：「分析一下」「把音量调大一点」——**没有对象、没有数值**，AudioMate 会停下来弹一张**意图澄清卡片**让你选，而不是瞎猜。

> 提示：「分析 / 锐评 / 点评 / 评估 / 检查 / 诊断 / 看看 / analyze / review」这类词都会触发“分析”。如果你一开始就说清范围（附上音频文件、或说“整个工程”、或说“选中对象”），就不会弹澄清卡片，直接执行。

### 示例对话

```
列出当前工程里所有的 Event
RTPC 是什么？怎么绑定到音量上？
（先在 Wwise 选中几个 Sound）分析所选对象源文件的响度，按从响到轻排序
把选中对象的音量统一降低 3 dB
```

## 5. 两种模式：Ask Mode 与 Agent Mode

顶部的 **`Mode`** 下拉决定了 AudioMate 的“权限等级”。这是最重要的一个概念。

| | **Ask Mode（提问模式）** | **Agent Mode（代理模式）** |
|---|---|---|
| 定位 | **只读**：能看，不能改 | **完全控制**：能改工程、写文件 |
| 能做 | 查询工程、试听、读本地文件、分析响度、检测异常、校验结构 | 上面全部 **＋** 修改属性、创建/删除对象、导入音频、归一化文件、保存工程、跑 PowerShell |
| 安全 | 任何写操作被**底层拦截** | 每个改动都会**先弹确认**再生效 |

**怎么用**：
- 问“是什么 / 多少 / 帮我分析”这类问题 → 留在 **Ask Mode**。
- 真要改工程或文件（调音量、建对象、导入、归一化）→ 先切到 **Agent Mode** 再发送。

**示例**：
```
Ask Mode：当前选中对象的音量是多少？
Agent Mode：把选中对象的音量调到 -6 dB
```

> 🔒 **安全是多层强制的，不只是“提醒 AI”**：Ask Mode 下，实时连接被包成只读客户端（任何非只读的 WAAPI 调用直接拒绝），写工具（写文件、归一化、批量修复 apply、导入、PowerShell）被替换成会报错的占位函数，生成的代码还会被静态扫描拦截本地写操作。所以在 Ask Mode 让它改东西，它只会解释“需要切到 Agent Mode”，而不会真的动手。
>
> 模式切换对**下一轮**生效；已经在后台跑的任务保持它启动时的模式。

## 6. 你会看到的确认弹窗

在 Agent Mode 下，**真正会造成改变的动作都会先暂停、等你点确认**。一共有这几种：

### 弹窗 1：Wwise 工程改动确认（Confirm / Revoke）

Agent Mode 代码真正改了 Wwise 工程后，改动会被包进一个撤销组，并弹出卡片 `Operation executed. Please confirm or revoke.`：
- 点 **`Confirm (Keep)`** → 保留改动。
- 点 **`Revoke (Undo)`** → 一键撤销（调用 Wwise 的 undo）。

> 只有 Agent Mode **且检测到真实写入**时才出现；纯读取操作不会触发。确认前输入框被禁用。

### 弹窗 2：本地文件写入确认

Agent Mode 要写本地文件（报告、技能包、归一化后的音频、生成的文件夹）时，内容**先缓存在内存里**，弹出卡片 `📝 以下文件将被写入，请确认：` 并列出所有路径：
- 点 **`✅ 确认写入`** → 真正落盘。
- 点 **`❌ 取消`** → 全部丢弃。

> Ask Mode 永远到不了这一步（写工具被直接禁用）。

### 弹窗 3：PowerShell 运行确认

你明确要求执行 Windows 命令时，会弹出**模态对话框**显示完整命令、工作目录，让你批准后才运行。**每次调用都必须确认**，仅 Agent Mode 可用。

### 弹窗 4：导入第三方 Python 模块的权限

生成的代码默认只能 import 安全白名单内的模块（json/re/os/math/datetime 等）。若代码要 import 白名单外的模块（比如 `pandas`），会弹窗问 `想要 import 模块 … 是否允许本次执行？`：
- 点 **Yes** → 本次允许（之后同一模块不再问）。
- 点 **No** → 拒绝（抛 ImportError）。

### 意图澄清卡片（INTENT_CLARIFY）

当你的请求确实含糊（尤其是没说范围的“分析一下”），AudioMate **不会瞎猜**，而是给你 2–3 个互斥选项卡片，例如：
```
分析本地音频文件 / 分析 Wwise 工程 / 分析所选对象源文件
```
点你想要的那个，它就按这个范围继续。

## 7. 音频分析与一键修复

这是 AudioMate 最强的一组能力。**你不用记工具名**——直接说需求，AI 会自动选对工具。下面列出每个工具能干什么、怎么触发、要注意什么。

> 📌 **读类工具**（分析、体检、检测、校验）在 **Ask / Agent 两种模式都能用**；**写类工具**（归一化、批量修复）**只能在 Agent Mode** 用。

### 7.1 单文件分析

**能做什么**：分析一个本地音频文件（WAV/FLAC/OGG/MP3 等），返回：声道数、采样率、时长、峰值 dBFS、RMS dBFS、**真峰值**（ITU-R BS.1770 标准的 4 倍过采样采样间峰值）、**积分响度 LUFS-I**、瞬时响度最大值 LUFS-M Max、响度范围 LRA，以及频谱信息（质心、带宽、滚降、平坦度、主导频率等）。

**怎么说**：
```
帮我分析一下 D:\game_audio\explosion.wav 的响度和峰值
```

**注意**：
- 文件必须存在且能解码（空文件会报错）。
- **超过 5 声道**（如 5.1/7.1）会自动降混为单声道再测（结果为近似值，并给出警告）。
- **短于 400ms** 的音频会用补偿后的 LUFS-M Max 近似 LUFS-I。
- 短于约 3 秒时 LRA 无统计意义，返回空。

### 7.2 目录批量分析

**能做什么**：扫描一个文件夹（默认递归、默认只看 `.wav`），逐个分析并汇总成报告：每文件一行，外加 summary（已分析数、总时长、平均/最大/最小 LUFS-I、最大真峰值）。

**怎么说**：
```
扫描 D:\Wwise\Originals\SFX 文件夹里所有 wav 的响度，给我一个汇总表
```
**注意**：默认只匹配 `.wav`，要分析其他格式需说明扩展名。

### 7.3 选中对象 / 全工程源文件分析

- **选中对象**（先在 Wwise 选好对象）：`分析我现在选中的这些 Sound 的源文件响度`
- **整个工程**（只有你明确说“整个工程”才会用）：`把整个 Wwise 工程里所有源音频文件的响度都分析一遍，列出超标的`

> 两者都需要 Wwise 处于连接状态。全工程分析较慢，文件多时建议加数量上限。

### 7.4 全链路响度估算

**能做什么**：估算选中对象**播放到总线输出时**的最终响度，而不只是源文件响度。它会把源文件 LUFS-I 加上整条增益链（对象 VolumeOffset + 祖先层级的 Volume/MakeUpGain + 总线 Volume）。

**怎么说**：
```
我选中的这些音效，经过 Actor-Mixer 和总线音量之后，最终输出大概是多少 LUFS？
```
**注意**：是**静态估算值**，不含 RTPC / State / 动态衰减；总线最多追踪 12 层。

### 7.5 单文件归一化（写操作，需 Agent Mode）

**能做什么**：把一个文件的积分响度归一化到目标 LUFS（默认 -16）。流程：测原始响度 → 归一化 → 防削波缩放 → **默认先备份原文件为 `*.bak.*`** → 以原格式写回 → 重新测量验证。

**怎么说**（**Agent Mode**）：
```
把 D:\audio\vo_line_01.wav 归一化到 -16 LUFS，记得备份原文件
```

### 7.6 响度合规体检

**能做什么**：只读地体检一个文件夹，判定每个文件是否落在目标响度区间（默认 -16 ~ -12 LUFS）且真峰值不超限（默认 -1 dBFS）。给每文件一个判定 `pass / fail / unknown` 和问题码（响度偏低/偏高/真峰超标），并按严重程度从大到小排出**不合规清单**。自动排除 `.bak` 备份文件。

**怎么说**：
```
检查 D:\Wwise\Originals\VO 里的语音是否都在 -16 到 -12 LUFS、真峰值不超过 -1 dBFS，把不合规的列出来
```

### 7.7 批量归一化

**这是最重要的安全设计：两步走，防止误改。**

- **第一步（预演 / dry run）**：你说“把某文件夹归一化到目标 LUFS”，AudioMate **默认只生成计划**——列出哪些文件要改、当前 vs 目标响度、需要的增益——**不写任何文件**。
- **第二步（应用 / apply）**：你看完计划确认无误，说“执行 / 应用”，它才真正写盘（不可逆），并逐个备份。

**怎么说**：
```
把 D:\Wwise\Originals\SFX 批量归一化到 -16 LUFS
（看完预演计划后）确认没问题，执行吧
```
**注意**：默认 `only_noncompliant=True` 只处理不合规文件；目标“已合规”区间默认是目标值 ±0.5 LU。

## 8. 工程体检：异常检测与结构校验

### 8.1 音频缺陷检测

**能做什么**：检测音频文件的常见缺陷。它在做响度/频谱分析**之前**先跑检测，所以空文件、静音、超短文件也能得到结论而不报错。检测项（异常码）：

| 异常码 | 含义 |
|--------|------|
| `empty` | 空文件 / 无法解码 |
| `silent` | 整体 RMS 低于 -60 dBFS（近乎静音） |
| `clipping` | 连续 ≥3 个采样达到/超过 0.999（真·削波，不是单点峰值） |
| `true_peak_over` | 采样间真峰超过 0 dBFS |
| `dc_offset` | 直流偏移 > 0.01 |
| `too_short` | 时长 < 0.1 秒 |
| `abnormal_sample_rate` / `abnormal_channel_count` | 采样率 / 声道数不符合期望（需配置期望值，见第 10 节） |

**怎么说**：
```
检测一下 D:\audio\gunshot.wav 有没有削波、静音或直流偏移之类的问题
扫描 D:\Wwise\Originals 整个目录，找出所有有削波、静音、采样率不对的文件，按问题类型统计
```
> 目录扫描是轻量的（跳过 LUFS/频谱，比响度分析快），只返回有问题的文件 + 按异常码统计，并自动排除 `.bak` 备份。

### 8.2 工程结构校验

**能做什么**：按团队规则（`audio_rules.json`，见第 10 节）审计 Wwise 工程，发现三类问题：

- **空容器**（`empty_container`）：RandomSequence / Switch / Blend 容器、ActorMixer、Folder/WorkUnit 等没有任何子对象。
- **缺失源文件**（`missing_source_file`）：对象设了源文件路径，但本地文件不存在。
- **命名违规**（`naming_violation`）：对象名不符合该类型的命名正则。

**怎么说**：
```
按团队命名规范检查整个 Wwise 工程，找出空容器、命名不规范的对象，以及源文件丢失的对象
```
**注意**：
- 必须**连接 Wwise**，否则返回警告空结果。
- `scope='project'` 查整个工程层级根，`scope='selection'` 只查当前选中及后代。
- **命名规则默认是空的（每个名字都通过）**，需要先在配置文件里写正则才会生效——这是刻意的“零误报”设计。

## 9. 搭建 Wwise 侧声音系统：HDR / NPC / 环境音 / 武器 / UI

AudioMate 不只适合做单次分析和批量修改，也可以帮你**搭建 Wwise 侧的声音系统骨架**。这里说的“系统”指的是 Wwise 工程里的层级、Bus、Event、RTPC、State、Switch、容器、命名规则和默认属性，而不是游戏引擎里的运行时代码。

### 9.1 它能做到什么，不能做到什么

**能做到**：

- 规划并创建 Wwise 对象层级，例如 Actor-Mixer、Random/Sequence、Switch Container、Blend Container、Event、Bus、AuxBus。
- 批量设置属性，例如 Volume、Pitch、Priority、Virtual Voice、Bus 路由、Output Bus、Attenuation 引用。
- 创建或绑定 RTPC、State、Switch，并按命名规范生成对象和 Event。
- 检查已有工程结构，找出缺失对象、命名不一致、路由错误或不适合的属性写入。
- 按你的项目规范生成“搭建计划”，让你确认后再落到 Wwise 工程。

**不能直接替代**：

- 游戏引擎里的触发逻辑，例如 NPC 何时播放脚步、环境区域如何判断、天气和战斗强度从哪里来。
- 运行时参数上报代码，例如 Unity/Unreal 调用 `SetRTPCValue`、`SetState`、`PostEvent` 的时机。
- 最终听感判断。AudioMate 可以帮你搭结构和检查配置，但混音、动态范围和玩法反馈仍然需要试听和项目内验证。

### 9.2 推荐工作流

1. 先在 Ask Mode 里让 AudioMate 生成方案，不改工程：
   ```
   帮我设计一套 Wwise 侧的 NPC 声音系统，只要方案，不要修改工程。需要包含层级、Bus、Event、Switch、RTPC 和命名规范。
   ```
2. 你审阅方案，补充项目约束：
   ```
   我们项目里 NPC 分为 Human、Creature、Robot，脚步按 Surface Switch 区分，语音按 Alert State 区分。请按这个约束修改方案。
   ```
3. 切到 Agent Mode，让它先创建最小骨架：
   ```
   按刚才方案创建最小可用的 Wwise 侧 NPC 声音系统。先创建层级、Bus、State/Switch/RTPC 和空 Event，不导入音频。
   ```
4. 确认弹窗里检查改动；没问题再 Confirm。
5. 后续逐步导入素材、绑定源文件、跑结构校验和响度检查。

> 建议一次只让它搭一个系统的“第一版骨架”。不要一口气让它同时做 HDR、NPC、环境音、武器和 UI，全工程大改更难审阅，也更容易误伤。

### 9.3 HDR / 动态混音系统

适合让 AudioMate 帮你做这些 Wwise 侧工作：

- 规划高优先级、普通优先级、背景层的 Bus / Actor-Mixer 分组。
- 批量设置 Priority、Virtual Voice、Volume 范围和基础路由。
- 创建用于“战斗强度、距离、镜头关注度、玩家状态”的 RTPC。
- 检查关键声音是否路由到正确 Bus，是否有过高/过低的初始音量。

示例提示词：

```
Ask Mode：帮我设计一套 Wwise 侧 HDR / 动态混音系统。目标是让爆炸、武器、UI 提示优先级高，环境床和远处小声源优先级低。请输出层级、Bus、RTPC、Priority、Virtual Voice 和验证清单。
```

```
Agent Mode：按这个 HDR 方案创建 Wwise 侧最小骨架：Bus、Actor-Mixer 分组、RTPC 占位和命名规范。不要导入音频，不要覆盖已有对象；如果对象已存在就复用。
```

### 9.4 NPC 声音系统

适合让 AudioMate 搭建的内容：

- NPC 分类层级，例如 `NPC/Human`、`NPC/Creature`、`NPC/Robot`。
- 声音模块，例如 Footstep、Foley、Voice、Weapon、Ability、Damage、Death。
- Surface Switch、Alert State、Faction Switch、Distance RTPC 等控制入口。
- Event 命名，例如 `Play_NPC_Human_Footstep`、`Play_NPC_Creature_Attack`。
- 按分类批量创建空容器、空 Event 和路由。

示例提示词：

```
Ask Mode：帮我规划一套 NPC 声音系统。NPC 有 Human、Creature、Robot 三类；脚步用 Surface Switch，警觉程度用 Alert State，远近用 Distance RTPC。请给出 Wwise 侧层级、Event 命名、Switch/State/RTPC 设计和接入游戏代码时需要传的参数。
```

```
Agent Mode：在 Wwise 中按 NPC 声音系统方案创建第一版骨架。只创建对象、Switch/State/RTPC、Bus 路由和空 Event；所有已有对象先查询并复用，不要删除任何东西。
```

### 9.5 环境音系统

适合让 AudioMate 搭建的内容：

- Ambience 总层级、区域层级、天气层级和昼夜层级。
- 循环床、随机点声源、远景声、室内/室外分层。
- Weather State、TimeOfDay RTPC、Area State、Intensity RTPC。
- 环境音 Bus、AuxBus、混响发送和基础响度检查。

示例提示词：

```
Ask Mode：帮我设计一套开放世界环境音 Wwise 侧系统。需要支持区域、天气、昼夜、室内外和随机点声源。请输出层级结构、State/RTPC、Bus 路由、Event 命名和测试清单。
```

```
Agent Mode：按环境音系统方案创建 Wwise 侧骨架：Ambience 层级、区域 State、Weather State、TimeOfDay RTPC、环境音 Bus 和空 Event。不要导入音频，先复用已有对象。
```

### 9.6 武器系统

适合让 AudioMate 搭建的内容：

- 武器分类层级，例如 `Weapon/Pistol`、`Weapon/Rifle`、`Weapon/Shotgun`、`Weapon/Heavy`。
- 发射结构，例如 Fire、Tail、Mechanical、Reload、DryFire、Equip、Holster、Impact。
- 第一人称 / 第三人称 / 远距离版本的分层和 Bus 路由。
- WeaponType Switch、FireMode Switch、Surface Switch、AmmoState State、Distance RTPC、IndoorOutdoor State。
- Event 命名，例如 `Play_WPN_Rifle_Fire_1P`、`Play_WPN_Rifle_Tail_Outdoor`、`Play_WPN_Impact_Metal`。
- 基础混音检查，例如武器主声、尾音、机械层、命中层是否路由到正确 Bus，是否会互相盖住。

示例提示词：

```
Ask Mode：帮我设计一套 Wwise 侧武器声音系统。需要支持第一人称、第三人称、远距离尾音、换弹、空枪、命中材质和室内外尾音。请输出层级、Bus、Event 命名、Switch/State/RTPC 设计和测试清单。
```

```
Agent Mode：按武器声音系统方案创建最小 Wwise 骨架。创建 Weapon 层级、武器 Bus、WeaponType/FireMode/Surface Switch、Distance RTPC、IndoorOutdoor State 和空 Event；不要导入音频，已有对象先复用。
```

### 9.7 UI 声音系统

适合让 AudioMate 搭建的内容：

- UI 分类层级，例如 Navigation、Confirm、Cancel、Popup、Inventory、Reward、Warning、System。
- Event 命名，例如 `Play_UI_Click`、`Play_UI_Back`、`Play_UI_Confirm`、`Play_UI_Reward_Rare`。
- UI Bus、Ducking 关系和优先级，避免 UI 被战斗或环境声盖住。
- UIContext State、MenuLayer State、Rarity Switch、FocusLevel RTPC 等控制入口。
- 一致性检查，例如按钮族是否命名一致、是否都有 Event、是否路由到 UI Bus。

示例提示词：

```
Ask Mode：帮我设计一套 Wwise 侧 UI 声音系统。需要覆盖导航、确认、取消、弹窗、背包、奖励、警告和系统提示；要求 UI 声音在战斗中也清晰。请输出层级、Bus、Event 命名、State/Switch/RTPC 和验收清单。
```

```
Agent Mode：按 UI 声音系统方案创建 Wwise 侧最小骨架。创建 UI 层级、UI Bus、UIContext/MenuLayer State、Rarity Switch 和空 Event；不要导入音频，不要覆盖已有对象。
```

### 9.8 评测复杂系统实现程度

复杂系统不能只看“对象有没有创建”，还要看它是否形成了可继续制作、可接入游戏、可扩展的 Wwise 设计。你可以让 AudioMate 在搭建后做一次只读验收：

```
Ask Mode：检查刚才创建的武器声音系统实现程度。请按结构完整度、控制入口、运行时接入准备、Bus 路由、可扩展性、幂等安全和验收清单打分，并列出缺失项。
```

建议按 100 分制看结果：

- **结构完整度**：Actor-Mixer、Container、Event、Bus 层级是否覆盖核心模块。
- **控制入口**：RTPC、State、Switch、Game Parameter 和 Event 命名是否足够游戏侧调用。
- **运行时接入准备**：是否说明程序侧需要传什么参数、何时 PostEvent、何时 SetState/SetSwitch/SetRTPC。
- **路由与混音安全**：是否路由到正确 Bus，是否有基础 Volume、Priority、Virtual Voice、Ducking 或发送设计。
- **可扩展性**：新增 NPC、武器、区域或 UI 类型时，是否能自然扩展。
- **幂等与安全**：是否复用已有对象、不覆盖、不删除、不制造重复结构。
- **可观测与验收**：是否输出对象清单、未完成项、试听清单和后续制作建议。

更完整的评测方法见 [Wwise 操作正确率与复杂系统评测](wwise-operation-evaluation.md)。

### 9.9 把系统方案沉淀成 Skill

如果你的团队经常搭类似系统，推荐把方案写成 Skill。Skill 里可以放：

- 系统目标和边界。
- 标准层级结构。
- 命名规范。
- 必须创建的 Bus、Event、State、Switch、RTPC。
- 禁止事项，例如“不删除已有对象”“不猜 GUID”“写入前先查 schema”“先生成计划再执行”。
- 验收清单，例如路由检查、空容器检查、命名检查、响度检查。

之后你就可以这样说：

```
使用 NPC 声音系统 Skill，给当前 Wwise 工程创建一套 Robot NPC 的声音系统骨架。先输出计划，等我确认后再执行。
```

## 10. 团队规则配置：audio_rules.json

第 8 节的结构校验和采样率/声道检测，背后都靠一份**可编辑的配置文件** `audio_rules.json` 驱动。

### 文件位置

- **开发态**（从源码运行）：工程根目录 `<项目根目录>\audio_rules.json`
- **安装态**（发布包）：`%LOCALAPPDATA%\AudioMate\audio_rules.json`

> 首次用到时，如果文件不存在，AudioMate 会**自动写入一份默认配置**供你修改。你只需在文件里写**想覆盖的键**，其余沿用内置默认（深度合并）。

### 配置结构

```json
{
  "naming": {
    "patterns": {
      "sound": "^(SFX|VO|MUS)_.*"
    },
    "ignore_types": ["workunit", "folder", "virtualfolder"]
  },
  "audio": {
    "expected_sample_rates": [48000],
    "expected_channels": [1, 2]
  },
  "structure": {
    "flag_empty_containers": true,
    "flag_missing_source_files": true
  }
}
```

- **`naming.patterns`**：`对象类型（小写） → 对象名必须完整匹配的正则`。默认是**空的**（不强制命名）。上例要求所有 `Sound` 对象名必须以 `SFX_`/`VO_`/`MUS_` 开头。
- **`naming.ignore_types`**：跳过命名校验的类型（默认 workunit/folder/virtualfolder）。
- **`audio.expected_sample_rates` / `expected_channels`**：期望的采样率 / 声道数。默认空列表 = 接受任意。**这两项被结构校验和音频异常检测共用**——配一次，两边都生效。
- **`structure`**：是否检查空容器、缺失源文件（默认都开）。

**怎么用**：直接用文本编辑器改这个文件，然后让 AudioMate 重新跑校验/检测即可。

> 提示：JSON 格式写错（解析失败）会静默回退到内置默认值；无效正则会被忽略不阻塞。

## 11. 扩展能力：知识库 / 技能 / 插件 / 市集 / MCP

AudioMate 不只操作 Wwise，还能接入五类扩展，把团队规范、外部系统、常用流程都拉进同一个对话里。

### 11.1 知识库（Knowledge）— 让 AI 懂你的项目

**是什么**：本地创建多个知识库，每个可上传项目规范、设计文档、表格等。提问时 AudioMate 会从知识库检索最相关的文本片段，作为“项目上下文”参考。

**怎么用**：
1. 点左侧 **`📚 Knowledge`**。
2. 点 **`＋ 新建知识库`** 输入名称。
3. 点 **`📄 上传文档`** 选文件，或**直接把文件拖进窗口**。
4. 回到聊天页，在底部 **`📚 知识库`** 下拉里选目标库（也可不选，自动跨全部库匹配）。
5. 提问时写明“参考当前知识库”并说清要检查的规则/章节。

**支持格式**：`.txt .md .csv .json .xml .html .log .pdf .docx .xlsx .pptx`

**示例**：
```
先在 Knowledge 里新建「项目音频规范」并上传规范 PDF 和命名表 Excel，
然后选中该知识库后问：参考项目音频规范，检查当前选中对象的命名和响度是否符合要求
```
> 注意：PDF 需装 PyPDF2、Word 需 python-docx、Excel 需 openpyxl、PPT 需 python-pptx，否则该文件无法解析。检索是**关键词匹配**（非语义向量），提问用词最好和文档术语一致。**不要把密钥/账号放进知识库。**

### 11.2 技能（Skill）— 复用团队经验

**是什么**：把团队的检查清单、任务规则、Agent 行为（角色、输出格式、安全边界）固化成一个“技能”。一个 Skill 是一个目录，含 `manifest.json`/`skill.json` 或带 frontmatter 的 `SKILL.md`。

**怎么用**：
- **本地安装**：`Settings > Skill 区域 > ＋ 新增 Skill`，选 Skill 目录，导入后用开关启用。
- **使用方式**：聊天页 Skill 选择器保持 **`Auto Skill`**（系统按问题自动匹配最相关的已启用技能），或**手动指定**某个技能（强制本回合应用）。

**示例**：
```
把团队「响度检查 + QA 报告」流程做成 Skill 导入并启用；
保持 Auto Skill 时直接问「检查当前选中对象的响度风险并出 QA 报告」即会自动套用
```
> Skill 只影响**提示词与行为**，本身不提供可执行工具（工具来自 Plugin/MCP）。

### 11.3 插件（Plugin）— 连接外部软件

**是什么**：加载本地 Python 代码，向 Agent 注册可调用的工具（工具名形如 `plugin.<插件id>.<工具名>`）。适合把外部软件、批处理脚本、内部工具变成自然语言可用的能力。

**怎么用**：
- **本地导入**：`Settings > Plugin 区域 > ＋ 新增 Plugin`，选含 `plugin.json` 的插件目录。
- **扩展中心导入**：Market > 插件 > 导入本地插件目录；内置示例插件可直接配置。

> ⚠️ 插件会在你电脑上执行 Python 代码，**只导入可信来源**。插件必须在 Settings 里启用才会被加载。

### 11.4 扩展中心（Market）— 管理本地扩展

**是什么**：桌面内置的扩展中心，用来统一管理本地 Skill、Plugin 和内置示例插件。

**怎么用**：
1. 点聊天页右侧 **拼图按钮 🧩** 打开 Market。
2. 顶部切换 **`插件`** 或 **`技能`**。
3. 使用本地导入按钮选择 Skill 或 Plugin 目录。
4. 对内置插件，按卡片上的配置按钮完成本机设置。

> 开源版不内置远程扩展市场；需要团队分发扩展时，可以把插件目录或 Skill 目录随仓库、压缩包或内部制品仓库发布。

### 11.5 MCP — 对接外部系统

**是什么**：用 MCP 标准协议接入外部工具或团队系统。支持 stdio（本地命令）和 URL（远程）两种方式，可保存多个配置并各自启停、按顺序定优先级。

**怎么用**：
1. `Settings > MCP 配置 > 新建配置`，填名称并粘贴 MCP JSON。
2. 保存后用开关**启用**（新建后默认是关闭的，记得打开）。
3. 用上移/下移调整优先级。

**示例**：
```
用 MCP 工具查询我们项目的最新音频交付清单
```
> 多个配置暴露同名工具时，**靠前的优先**。需安装 mcp 依赖。

## 12. 进阶功能：定时任务 / 本地文件 / 联网 / 副宠 / REAPER

### 12.1 定时任务（⏰）

**是什么**：让 AudioMate 在指定时间/周期自动开始一段对话任务。支持一次性、每天、每周、按分钟间隔。

**怎么用**：
1. 点左侧 **`⏰ 定时任务`**。
2. 填**标题**和**要发给 Agent 的提示词**（必填）。
3. 选调度类型（每周需勾至少一个星期几）。
4. 勾“启用”并保存。列表里每条可“立即执行/编辑/删除/启停”。

**示例**：
```
标题「每日响度巡检」
提示词「分析 D:/GameAudio/SFX 目录所有 wav 的 LUFS，把超过 -16 LUFS 的列成报告写到桌面」
调度「每天 10:00」
```
> 到点时若 Agent 正忙，任务会排队，空闲后自动跑。

### 12.2 读写本地文件

- **读**：直接说路径，AudioMate 能读文本、CSV、Excel、Word、PPT，也能列目录。需要时会弹系统文件选择框让你授权。
  ```
  读取 D:/ProjectDocs/命名规范.xlsx 的第一个表，按这个规范检查我选中的 Wwise 对象命名
  ```
- **写 / 生成报告**（Agent Mode）：能写单个文件或一整套文件夹结构。**先暂存、弹确认卡片、你点确认才落盘**（见第 6 节弹窗 2）。
  ```
  把刚才的响度分析整理成一份 Markdown 报告，连同 README 一起放到 ~/Desktop/响度报告/ 文件夹里
  ```
> 单文件上限 5MB；文本读取超 20000 字会截断。

### 12.3 导入本地音频到 Wwise（Agent Mode）

先在 Wwise 选好要导入到的父对象，再让 AudioMate 把指定路径的音频导入：
```
把 F:/Renders 里这几个新渲染的 wav 导入到我现在选中的 Footsteps 文件夹下
```
> Wwise 必须有选中对象；不支持的扩展名/不存在的文件会被跳过。

### 12.4 联网与飞书

- **抓网页**：`读一下这篇 Wwise 官方文档 https://... 并用中文总结关键步骤`（只允许 http/https，拒绝内网/本机地址，下载上限 2MB）。
- **读飞书文档**：`读这份飞书需求文档 https://xxx.feishu.cn/docx/xxxx，把里面要做的音效列成表`（依赖飞书 MCP 已配置）。

> 这些**联网功能在 Wwise 断开时也能用**。

### 12.5 副宠（Buddy）— AI 分身协作

**是什么**：把任务委派给一个独立运行的“副宠”子 Agent，可并发派多个，各自有自己的模型和可用插件，也能绑定到定时任务。

**怎么用**：在 `Settings > Buddy（宠物）` 创建副宠（起名、设任务模板、选模型/插件），之后让主 Agent 委派，或给副宠绑定定时任务。

**示例**：
```
派副宠「响度检查员」去分析这批素材的 LUFS，同时让副宠「命名检查员」核对命名，最后汇总
```

### 12.6 REAPER 控制插件

**是什么**：通过 ReaScript 桥接（reapy）让 AudioMate 直接操作 REAPER：读工程、控制走带（播放/停止/录音）、增删改轨道/FX/marker/region/MIDI、改渲染设置、触发渲染。

**怎么用**：
1. 在 Market 找到 **Reaper Control** 卡片，点 **`配置`**（AudioMate 会写入 REAPER 的 Python 设置、备份 `reaper.ini`、安装 bootstrap 脚本）。
2. **重启 REAPER**，在 Action List 里运行一次 `AudioMate/audiomate_reapy_bootstrap.py`。
3. 回 AudioMate，让 Agent 执行 `plugin.reaper-control.check-connection` 验证连接。
4. 之后用自然语言让它控制 REAPER。

**示例**：
```
连接 REAPER，读取当前工程轨道列表，列出静音轨、独奏轨和带 FX 的轨道
```
> 必须先完成配置且 REAPER 已启动；写操作（render/改轨道等）会改当前工程，执行前确认工程可改。

## 13. 常见问题排查

| 现象 | 可能原因与解决 |
|------|----------------|
| 点 Connect 后显示 `○ 请打开Wwise或开启WAAPI` | Wwise 没开 / WAAPI 没启用 / 8080 被防火墙/杀毒/代理拦截。先确认 Wwise 在运行且 WAAPI 已开。 |
| AI 不回复或报认证错误 | 回 `Settings > 模型服务配置` 检查 Base URL 和 API Key 是否正确、是否点了“保存密钥”。 |
| 让它改东西却只解释“需要 Agent Mode” | 你在 Ask Mode。切到顶部 `Mode > Agent Mode` 再发送。 |
| 说“分析一下”后弹出选项卡片 | 请求太含糊。点选范围，或下次直接说清“选中对象/整个工程/某文件夹”。 |
| 针对“选中对象”的操作返回空 | Wwise 里没选中任何对象。先去 Wwise 的 Project Explorer 点选对象。 |
| 多声道（5.1/7.1）文件响度是“近似值” | 这是正常的——超过 5 声道会自动降混后测量，会给出警告。 |
| 命名校验没报任何违规 | `audio_rules.json` 的 `naming.patterns` 默认是空的，需要先配正则。 |
| 批量归一化没改文件 | 第一次调用是**预演**，不写文件。看完计划后说“执行/应用”才会真正落盘。 |
| 知识库里的 PDF/Word/Excel 读不了 | 缺对应解析库（PyPDF2 / python-docx / openpyxl / python-pptx）。 |
| 反馈/查日志 | 顶部状态栏的反馈按钮（📷）可打开反馈二维码和本地日志目录。 |

## 14. 新手 7 天上手路线

- **第 1 天**：装好、填密钥、连上 Wwise。在 **Ask Mode** 问几个问题（“列出工程里的 Event”“RTPC 是什么”），熟悉对话。
- **第 2 天**：在 Wwise 选中几个对象，用 Ask Mode 做**响度分析**和**全链路响度估算**。
- **第 3 天**：切到 **Agent Mode**，做一次**单文件归一化**，体验 Confirm/Revoke 和文件写入确认弹窗。
- **第 4 天**：对一个素材文件夹做**响度合规体检** + **批量归一化（先预演后应用）**。
- **第 5 天**：跑**异常检测**和**工程结构校验**；编辑 `audio_rules.json` 配上你团队的命名规范和采样率要求。
- **第 6 天**：建一个**知识库**上传项目规范，让 AI 参考它做检查；导入一个本地 **Skill**。
- **第 7 天**：用第 9 节的方法，让 AudioMate 先设计一套 **NPC / HDR / 环境音 / 武器 / UI** 的 Wwise 侧系统方案，再在 Agent Mode 下创建最小骨架；有需要的话配 **REAPER 插件** 或 **MCP**。
